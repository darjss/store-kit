# Product

## Register

product

## Platform

web

## Users

The primary user is a Mongolian store owner or staff member who manages products, inventory, orders, payments, and checkout settings during business hours. The admin is used mainly from a phone in a bright shop. Desktop use is secondary and supports denser operational work.

## Product Purpose

Store Kit makes it fast to launch and operate one credible Mongolian online store. Each store has its own infrastructure and data. The shared admin must make routine commerce work direct, safe, and understandable without requiring technical knowledge.

Success means an operator can identify urgent work, add a sellable product, update stock, process an order, and change checkout settings quickly from a phone.

## Positioning

A practical store operating tool that gives each Mongolian business a complete independent store without multi-tenant SaaS complexity.

## Brand Personality

Practical, calm, and trustworthy. The interface speaks plainly, favors familiar retail concepts, and feels dependable during repetitive daily work. User-facing admin copy is Mongolian-first.

## Anti-references

Do not make the admin look like a dark developer console, a generic AI dashboard, or an unmodified component registry. Avoid automatic purple or violet accents, decorative icon tiles, blanket icon use, gradients, glass effects, repeated floating card grids, tiny controls, squeezed desktop tables, and technical implementation language.

Do not copy Shopify or Square. Use their mobile retail clarity and task focus as reference points only.

## Design Principles

1. Start with the next real retail task, not a general metric.
2. Design for one-handed phone use first, then add desktop density.
3. Show only the information needed for the current decision.
4. Use plain Mongolian commerce language and hide implementation details.
5. Make risky actions explicit and preserve the operator's work.

## Accessibility & Inclusion

Meet WCAG AA. Use visible focus, semantic structure, text labels, reduced-motion support, and status communication that does not depend on color alone. Mobile touch targets are at least 44 by 44 CSS pixels. Inputs use text that remains readable without zoom. Support keyboard operation on desktop and touch operation without hover dependencies.
